# Oistars Billings

A comprehensive billing, invoicing, client store ledger, and recurring subscription platform designed for modern businesses and e-commerce brands. Built with Kotlin and Jetpack Compose adhering to high-density Material 3 design principles.

![Oistars Billings Banner](./assets/billing_dashboard_hero.jpg)

---

## Overview

**Oistars Billings** provides an integrated workspace to create, monitor, and manage client accounts, invoices, line items, and payment transactions. Designed for maximum information clarity and rapid operational throughput, it features a high-density dashboard with instant search, status filtering, and ledger summaries.

### Key Capabilities
- **Invoice Lifecycle Management**: Draft, send, mark as paid, or cancel invoices with automated subtotal, tax/VAT, and discount calculations.
- **Client Ledger & Accounts**: High-density client directory tracking lifetime billing, outstanding balances, and active account status.
- **Real-Time Financial Metrics**: Instant calculation of total billed revenue, pending collections, overdue amounts, and tax obligations.
- **Offline-First Architecture**: Powered by a robust local Room SQLite database with transactional consistency and reactive Kotlin Flows.
- **Enterprise Security & Optimization**: Production release builds protected with R8 code shrinking, resource stripping, and ProGuard obfuscation rules.

## Security Policy

We treat the security and confidentiality of financial records and customer transaction data with top priority.

### Reporting a Vulnerability
If you discover a potential security vulnerability within Oistars Billings, please do not open a public issue. Instead, report it through responsible disclosure channels:
- Email: `security@oistars.example.com` or direct contact via your AI Studio organization administrators.
- Please include steps to reproduce, impact analysis, and device environment details.
- We acknowledge receipt within 48 hours and provide remediation timelines according to severity.

### Security Architecture & Safeguards
- **Local Sandbox Storage**: Application data is isolated within Android's protected internal app storage sandbox, preventing unauthorized inter-process access.
- **Credential Hygiene**: API keys and environment credentials are provided via secure build configuration (`BuildConfig` / platform secrets panel). No secrets or private keys are hardcoded into the source tree.
- **Code Shrinking & Obfuscation**: Release builds utilize R8/ProGuard to remove unused code, strip debugging metadata, and obfuscate sensitive class symbols.
- **Zero Insecure Reflection**: Data models and database entities are strictly typed, avoiding dynamic reflection attack surfaces.

## Data Policy & Privacy

Oistars Billings is architected with a **privacy-by-default, local-first** data model:

### 1. Data Collection & Storage
- **What We Store**: Client profiles (name, email, company, address), invoice entries, line items, and transaction logs entered directly by the user.
- **Where It Lives**: All primary operational data resides exclusively in your device's local Room database (`AppDatabase`).
- **No Third-Party Telemetry**: The application does not bundle behavioral tracking SDKs, advertising IDs, or background analytics beacons.

### 2. User Data Ownership & Control
- **Full Data Sovereignty**: All entered client and invoice data belongs exclusively to you.
- **Deletion**: Clearing application data via Android system settings or uninstalling the app permanently purges the local database and all associated records.
- **Exportability**: Data can be viewed, filtered, and generated into invoice previews for printing, PDF generation, or records retention without third-party vendor lock-in.

### 3. Platform & Permission Compliance
- **Zero Broad Storage Permissions**: In adherence with Google Play Developer policies, the app does not request broad external storage permissions (`READ_EXTERNAL_STORAGE` or `WRITE_EXTERNAL_STORAGE`).
- **Network Access**: Restricted strictly to authorized API synchronization and server-side assistant capabilities as configured in `metadata.json`.

## Technology Stack
